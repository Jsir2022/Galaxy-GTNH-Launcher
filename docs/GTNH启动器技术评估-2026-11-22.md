# GTNH 启动器需求与技术评估

2026-11-22 · 已确认产品方向，待实现与验证

## 玩家流程

- 首版发布 Windows 和 Linux 便携包，随包附带对应平台的 Java 25。玩家只需取得启动器，首次运行选择一个可写目录，并在浏览器完成微软正版授权。首次授权和下载需要联网。
- 启动器自动准备 Minecraft、Forge、游戏库、资源和 GTNH 内容，验证安装结果后使用内置 Java 启动。玩家无需提前安装 Java 或 Minecraft，也无需手动配置 JVM、整合包或实例。
- 后续运行复用安装目录与有效登录会话，自动检查启动器自身更新和整合包更新，完成后打开游戏。界面只呈现目录选择、授权、进度、错误与重试等必要操作。

## 技术选型与参考项目

- 采用 Qt 6，建议使用 C++、CMake 和 Qt Widgets。首批测试建议覆盖 Windows x64 和 Linux x86_64，具体 Qt 小版本、Windows 最低版本及 Linux 发行版范围按双端打包和实测确定。[Qt 6.8 平台支持](https://doc.qt.io/qt-6.8/supported-platforms.html)
- PCL2 是 Minecraft 启动逻辑的主要参考。重点阅读版本元数据、库和资源下载、Forge 参数生成和启动日志。PCL2 的 WPF 桌面工程与 Qt 跨平台目标不同，采用独立 Qt 实现。引入源码前核对所选仓库、提交和文件的许可。[PCL2](https://github.com/Hex-Dragon/PCL2) · [PCL-CE 许可说明](https://github.com/PCL-Community/PCL-CE/blob/dev/README-EN.md)
- packwiz 可参考源码，包括清单、按哈希比较、增量下载与受管文件移除。是否兼容 packwiz 格式留待发布流程设计时决定。旧 Galaxy 2.8.4 有 packwiz 发布和回退记录。[packwiz](https://github.com/packwiz/packwiz) · [旧服工作日志](../../../archives/legacy-server-snapshots/read-only/Galaxy_GTNH284_S1/docs/WORKLOG.md)
- 梦鱼和 Prism 只作为参考。重点参考签名校验、安装中断恢复和玩家文件保护。现有梦鱼工作树保留，独立项目实现新的启动流程。[梦鱼启动器说明](../../../gtnhlaoji/repos/DreamingFish-Prism/dreamingfish/README.zh-CN.md)

## 只允许微软正版登录

- 可参考开源启动器的微软 OAuth、Xbox/XSTS、Minecraft 会话及 Java 版游戏权益校验实现。使用项目自己的应用注册，确认 Minecraft API 接入权限与发布条件。
- 正版账号和有效游戏会话是启动前置条件。首次安装、新账号或会话需要重新授权时打开浏览器，后续优先刷新已保存会话。授权取消、无游戏权益、刷新失败或无法完成必要校验时，提示原因并停止启动。产品不提供离线账号、本地用户名登录或跳过正版校验的入口。
- 使用系统凭据存储保存刷新凭据，按目标平台验证。日志、源码、发行包与更新清单不得包含用户令牌、应用密钥或发布私钥。

## 更新与发布

- 程序更新与整合包更新独立。程序更新由辅助进程在主程序退出后替换已验证的发行文件。两条更新流程均验证发布来源、清单签名与文件摘要，保留中断恢复路径。
- 整合包发布固定官方 GTNH 版本、Java 变体、批准的差异与文件摘要。客户端以受管清单执行更新，保留存档、地图、按键等个人文件。首次下载的 Minecraft 文件及第三方模组按其允许的来源获取，发行前确认每项内容的再分发条件。
- 启动器按开源项目规划，发行二进制时同步提供对应源码、构建脚本和许可证。项目许可证待核对第三方源码后确定。
- Qt 的实际义务取决于模块、版本与链接方式。Qt 官方说明，在符合 LGPLv3 条件时，动态链接可以保留应用源码私有。采用开源发布仍需核对并履行使用模块、对应 Qt 源码、许可证与库可替换性等分发义务。Qt Network Authorization 在 Qt 6.8 的开源模块清单中适用 GPLv3，采用前需确认与项目许可证兼容。[Qt GPL/LGPL 义务](https://www.qt.io/development/open-source-lgpl-obligations) · [Qt 6.8 模块许可](https://doc.qt.io/qt-6.8/licensing.html)

## 首版验收

1. Windows、Linux 各在未安装 Java、Minecraft 和 GTNH 的干净环境中，从空目录完成首次授权和安装，以内置 Java 25 打开完整 GTNH 客户端并实际进入开启正版验证的测试服。
2. 第二次运行复用目录和有效会话，验证启动器自更新、整合包逐文件增量同步、下载中断后恢复，以及原有个人文件保留。
3. 验证取消授权、无 Java 版游戏权益以及会话失效且无法刷新时均无法启动。检查双端发行包可由对应源码构建，并包含所需第三方许可材料。
